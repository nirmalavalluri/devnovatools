How to Parse Log Files: Formats, Patterns and Tools

📅 August 18, 2026⏱ 6 min read 🛠️ Try the Log Parser →

Every production incident starts the same way: staring at a wall of log lines, trying to find the one that matters. This guide covers the log formats you'll actually run into, the regex to pull structured fields out of each, and when it's worth reaching for a real parser instead of grep.

Apache/Nginx Combined Log Format

This is the one you'll meet most often for web server access logs:

127.0.0.1 - frank [10/Oct/2026:13:55:36 -0700] "GET /apache_pb.gif HTTP/1.0" 200 2326 "http://www.example.com/start.html" "Mozilla/5.0"

Regex to pull out the key fields:

^(\S+) \S+ (\S+) \[([^\]]+)\] "(\S+) (\S+) (\S+)" (\d+) (\d+) "([^"]*)" "([^"]*)"

JSON Lines Logs

Modern applications increasingly log structured JSON, one object per line, which is far easier to query but still needs the right approach:

{"timestamp":"2026-08-18T09:12:03Z","level":"error","service":"api","message":"connection timeout","request_id":"a1b2c3"}
{"timestamp":"2026-08-18T09:12:05Z","level":"info","service":"api","message":"request completed","request_id":"a1b2c4"}

Because each line is standalone valid JSON, you don't need regex at all — parse each line with your language's JSON parser and filter on whatever fields you need:

# Find all error-level lines
cat app.log | jq -c 'select(.level == "error")'

# Extract just the messages
cat app.log | jq -r '.message'

Syslog Format

<34>Oct 10 22:14:15 mymachine su: 'su root' failed for lonvick on /dev/pts/8

The number in angle brackets is the priority value (facility × 8 + severity). Regex to extract the common fields:

^<(\d+)>(\w+\s+\d+\s+[\d:]+)\s+(\S+)\s+([^:]+):\s*(.*)$

Groups: priority, timestamp, hostname, tag/process, message.

grep, awk and Friends — When They're Enough

For a quick one-off look at a log file, the classic Unix tools are still the fastest option:

# Count requests per status code
awk '{print $9}' access.log | sort | uniq -c | sort -rn

# Find all 5xx errors
grep -E ' 5[0-9]{2} ' access.log

# Extract unique IPs
awk '{print $1}' access.log | sort -u

# Tail and filter in real time
tail -f app.log | grep --line-buffered "ERROR"

These get you far, but they fall apart fast once you need to correlate fields across lines, parse timestamps into a real date range, or handle multiple log formats in one pass.

Move past ad-hoc regex and grep pipelines once you find yourself:

Frequently Asked Questions

What's the difference between Common Log Format and Combined Log Format?
Combined Log Format is Common Log Format plus two extra fields: the referrer and the user agent. Nginx and Apache both default to Combined in most modern configs.

How do I parse a log file with an unfamiliar/custom format?
Look for the most stable delimiters first — brackets, quotes, and consistent field order are usually there even in custom formats. Build your regex outward from the parts you recognize (timestamp, IP, status code) rather than trying to match the whole line at once.

Is JSON logging actually easier to parse than plain text?
Almost always, yes — you trade a small amount of extra log volume (JSON is more verbose than plain text) for not needing any regex at all. Most log aggregation tools also prefer structured JSON input.
