Cron Expression Cheat Sheet — Every Schedule You'll Ever Need

📅 June 16, 2026⏱ 7 min read 🛠️ Try the Cron Tester →

Nobody memorizes cron syntax. You look it up, copy the expression, paste it, and move on. This page is the reference you'll keep coming back to — every common schedule, the field-by-field syntax, and the mistakes that silently break production jobs.

The 5 Cron Fields

A standard cron expression has five space-separated fields. Left to right, smallest unit to largest:

┌───────────── minute (0-59)
│ ┌───────────── hour (0-23)
│ │ ┌───────────── day of month (1-31)
│ │ │ ┌───────────── month (1-12 or JAN-DEC)
│ │ │ │ ┌───────────── day of week (0-7, 0 and 7 = Sunday)
│ │ │ │ │
* * * * *

The expression fires when all five fields match the current time. An asterisk (*) means "every value." A mnemonic: "Minute, Hour, Day, Month, Weekday" — left to right, small to big.

Operators

OperatorMeaningExample
*Every value* * * * * — every minute
,List of values0,15,30,45 — at minutes 0, 15, 30, 45
-Range9-17 — hours 9 through 17
/Step (every Nth)*/5 — every 5th value

Important: */5 in the minute field means "at minute 0, 5, 10, 15, 20..." — it is anchored to zero, not to the time you saved the job. If you save at 12:03, the next run is 12:05, not 12:08.

*Standard 5-field cron cannot express "last day of month." Some schedulers (Quartz, AWS EventBridge) support the L character: 0 0 L * *. For standard cron, use a wrapper script that checks if tomorrow is the 1st.

Business Hours Pattern

This is the most common real-world pattern — run during office hours on workdays:

*/15 9-17 * * 1-5

This means: every 15 minutes, between 9:00 AM and 5:59 PM, Monday through Friday. Perfect for health checks, sync jobs, or dashboard refreshes that only matter during business hours.

Platform Differences

Not all cron implementations are identical:

  • Standard crontab (Linux) — 5 fields, no seconds, no L/W/#
  • Quartz (Java/Spring) — 6-7 fields with seconds, supports L, W, #
  • AWS EventBridge — 6 fields with year, uses ? for unspecified day-of-month or day-of-week
  • GitHub Actions — standard 5 fields, runs in UTC only
  • Kubernetes CronJob — standard 5 fields, timezone configurable since v1.27

Common Mistakes

  • Forgetting the timezone — cron runs in the server's system timezone. A job set for 0 9 * * * runs at 9 AM server time. If your server is UTC and you're in EST, that's 4 AM your time. GitHub Actions always runs in UTC.
  • Day-of-month AND day-of-week — in standard cron, specifying both creates an OR condition. 0 0 15 * 5 runs on the 15th of every month and every Friday, not "Friday the 15th."
  • Overlapping runs — if a job takes 10 minutes and runs every 5 minutes, you'll have parallel instances. Use a lock file or flock to prevent overlap.
  • No error handling — cron swallows output by default. Redirect to a log: */5 * * * * /path/to/script.sh >> /var/log/myjob.log 2>&1
  • The */N trap — */5 runs at minutes 0, 5, 10... not "every 5 minutes from when I saved." If you save at 12:03, the next run is still 12:05.

Frequently Asked Questions

How do I test a cron expression before deploying?
Paste it into our Cron Tester to see a human-readable description and the next 5-10 run times. Or use Cron Builder to construct one visually.

Can cron run a job every 45 seconds?
No — standard cron's smallest unit is one minute. For sub-minute scheduling, use a loop inside the script, systemd timers, or a scheduler that supports seconds (like Quartz).

Does 0 */2 * * * run at every even hour or every 2 hours from midnight?
Every even hour: 0:00, 2:00, 4:00, 6:00... The step is anchored to the field's minimum (0 for hours). It does not mean "every 2 hours from when the job was created."

How do I run a job on the last day of every month?
Standard cron can't express this directly. Use a script wrapper: [ "$(date +\%d -d tomorrow)" = "01" ] && /path/to/job.sh. Or use a scheduler that supports the L character.
