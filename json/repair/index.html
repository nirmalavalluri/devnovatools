📖 What is JSON Repair?

JSON Repair fixes JSON that fails to parse because of common syntax issues — the kind that show up constantly in output copied from ChatGPT, Claude, Gemini or any other LLM. It strips markdown code fences and stray prose, removes trailing commas, converts single-quoted strings to double quotes, quotes unquoted keys, strips comments, and converts Python-style True/False/None to valid JSON — then tells you exactly what it changed.

💡 Example

Input
```json {name: 'Alice', active: True, tags: ['a','b',],} ```
Output
{ "name": "Alice", "active": true, "tags": [ "a", "b" ] }

🛠️ Common Use Cases

  • Fixing JSON pasted straight out of a ChatGPT or Claude response
  • Cleaning up JSON that still has its markdown code fence attached
  • Converting Python dict literals (True/False/None) to valid JSON
  • Recovering JSON from logs or config files with trailing commas
  • Turning JavaScript object literals (unquoted keys, single quotes) into strict JSON

❓ Frequently Asked Questions

Why is JSON from ChatGPT or Claude often broken? ▾
LLMs generate JSON as text, not through a real parser, so they commonly add trailing commas, wrap the output in markdown code fences, use single quotes instead of double quotes, leave object keys unquoted, or mix in Python literals like True, False and None.
What does JSON Repair fix automatically? ▾
It strips markdown code fences and surrounding prose text, removes trailing commas, converts single-quoted strings to double quotes, quotes unquoted object keys, strips // and /* */ comments, and converts Python-style True/False/None to true/false/null.
Is this the same as the JSON Validator or JSON Formatter? ▾
No. JSON Validator only reports errors, and JSON Formatter only re-indents already-valid JSON. JSON Repair is specifically for JSON that fails to parse — it attempts to fix the syntax first, then pretty-prints the result.
